# Verification and precise delivery claims

Use this checklist after any of the three editing routes. A stage may be complete without the later stages being available; report those boundaries rather than folding them into one “success”.

## Preserve the source and identity

- Keep the original source read-only and prove its full hash unchanged. Retain the exact input, returned screenshot or actual layout record, and confirmed plan privately.
- Recheck target slide/host/XML/relationship bindings. Count coverage by scientific membership, not merely shape count; verify the selected and deliberately omitted units.
- For code-based layout or preview work, compare every protected OLE payload and unknown/unmodified ZIP part byte-for-byte. Validate only the allowlisted changed parts and all touched relationships/content types.
- For real Origin native Save, literal payload byte equality is not expected. Compare the available scientific data, missing values, curves/bindings, layers, axes, fits and non-target graph properties before/after and after a separate reopen. State any uninspectable properties; do not infer universal preservation from a partial API snapshot.
- Preserve exact scientific strings, run structure, case, number–unit spaces, symbols, italics and sub/superscripts. Layout approval does not authorize spelling/unit “corrections”.

## Check code operations, not just filenames

For a bounded byte/record patch, list modified byte ranges and require all unknown/non-target bytes unchanged. For OOXML edits, verify exact old/new attributes/text runs and package parts. For an appearance-only SVG edit, compare scientific paths/strings, clips and external-content refusal. If geometry mapping is explicitly approved, test that declared mapping for curves, markers, ticks and clips rather than incorrectly demanding unchanged coordinate strings.

Validate every active/fallback representation separately: nonempty bytes, expected signature/content type, valid references and successful decoding/rendering. One SVG rendering correctly does not validate its PNG fallback. An external preview replacement does not update internal OlePres streams or native Origin content; an OLE refresh can restore another appearance.

Do not execute macros, external links or embedded instructions during rendering. Render a disposable output in isolation and do not save the scientific deck through a renderer merely to obtain a PNG.

## Inspect final pixels

Inspect the complete figure at its intended size and dense detail crops. Use the aesthetic and alignment modules for exact anchors and role-based glyph/stroke measurements. Check:

- Plot/image bounds, both sides of confirmed columns, row edges and actual title/panel-letter baselines.
- Final glyph size and font substitution after all transforms, not only nominal point values.
- Title-to-tick/axis gaps, annotations against every nearby marker/rotated boundary, and insets.
- Native text wrapping/autofit, clipped axes/labels, transparency, line hierarchy and source aspect/crop.
- Panel memberships and both connector endpoint associations.

A visible unresolved collision is not a full visual pass. A requested intermediate preview can still be delivered with that precise limitation. Do not describe a composition preview as finished typography.

For an old/new overlay, use identical dimensions, DPI, crop and origin. The bundled `scripts/source_edit/pixel_overlay.py` makes an exact-canvas comparison; it must not auto-register, translate, rotate or resize one image to hide drift. Keep separate originals as well as the overlay. A static montage from HTML geometry is not a browser screenshot; mocked JavaScript events are not a real browser test.

## Guide reversibility

Every final figure must include guides. In a PPT, keep all reference lines for the figure/slide in one uniquely identified independent native group behind content. Check horizontal and vertical frame/ink/baseline comparisons. Do not mix them with scientific or annotation groups. Removing only the guide group must restore clean content/coordinates exactly; prefer exact clean-slide-byte restoration and verify it. These are removable drawing shapes, not PowerPoint View Guides.

## Separate application evidence

Use a private report with an explicit status for each relevant stage:

1. Source read-only inventory and semantic grouping.
2. Unit/guard tests and source/output parse.
3. Protected content/package/data comparison.
4. Render and visual inspection.
5. Actual PowerPoint display/open/save, if performed.
6. Independent Origin native open/edit/save/cold reopen, if performed.
7. PPT OLE activation/refresh and all required cache/host representations, if performed.
8. Interactive page operations and, separately, actual user save/readback when applicable.

Use “not run” rather than “passed” for unavailable stages. A bridge request acknowledgment, DONE file or code exit status is not native/visual completion. A local browser test is not a verified hosted user session. A new native Origin export is not automatically a correctly reinserted PPT object.

## Deliver the requested result

- **Rough arrangement:** interactive HTML plus optional same-geometry preview; label it as composition intent.
- **Effect-only request:** a guide-visible image, with a clean companion only as an addition; say which source layers remain untouched.
- **Code-edited PPT:** a new deck with all reference lines in one independent native group per final figure/slide, plus a clean companion when wanted, with the actual preview/native-object scope and refresh limitation.
- **Native Origin work:** verified new native output/export, and a PPT only when a supported reinsertion and its stated checks were completed.

A final raster shows guide lines but cannot retain independently selectable/hideable native groups; state this format boundary. Do not substitute a clean-only final image or claim raster grouping.

Provide a short result, the artifact/link, and the few remaining decisions or limitations that matter. Do not dump private plans, source maps, bridge/session details or internal reports into user-facing attachments. Do not publish source material or share the skill beyond the user's requested personal installation.

## Rough stretching must not survive as final scientific distortion

Check final glyph aspect, axes/tick geometry, circular markers, stroke widths, source-image physical aspect and scale bars against intact sources. Draft stretch expresses emphasis only. Re-render through the approved supported source/appearance route; do not certify a flattened stretched thumbnail/cache as refined output. Keep measurement imagery's draft warning separate from final correction, and let only verified non-measurement schematic body proportions adapt. Preserve original data and scientific meaning throughout.
