# Bounded native-patch methodology

Treat a supplied exact-source toolkit as a bounded capability, not a general Origin editor. Inspect its actual format, dependencies, provenance, license, integrity manifest and implementation before use. Distinguish static artifact consistency, executed synthetic tests, real Origin cold loading, native Save and full PPT/OLE refresh; one stage never proves the next.

Keep private source hashes, offsets, scientific PPT/OPJU files, candidates, machine paths and historical reports outside reusable resources. Do not run unknown code or activate a bridge merely because attached documentation describes it. A package without a license is not an openly licensed dependency; retain only independently documented methods unless the requested reuse is authorized.

Fixed-source examples may support only one frozen input and predefined operations. Do not generalize them to arbitrary colors, dimensions, composable patches or another project. No native writer, bridge launcher or MCP installer is added by this reference.

## Transferable safe method

1. Identify the exact native payload/stream and immutable source. A matching extension or graph appearance is not enough. Bind complete source hash, profile version and format assumptions.
2. Define a minimal field-specific operation with exact expected old bytes/values, supported ranges/length/encoding and invariants. Never replace the profile hash or offsets to force a different file through. Never change reserved/unknown bytes or infer a native serializer from a data reader.
3. Inspect the proposed diff in dry-run. Refuse stale input, unknown operation, unsupported parameter and existing/aliased output. If a reviewed implementation uses same-length patches, keep length and untouched-region guards; variable-length work is a new unsupported operation until separately implemented and tested.
4. Publish a new output exclusively. A no-overwrite filesystem primitive may be unsupported on a VM shared folder; report that issue instead of weakening it to overwrite. Use a verified local staging destination only within authorization.
5. Check exact allowed byte changes and protected scientific inventory. For native Save, compare semantic invariants too because legitimate application serialization can change many bytes. Record datasets including missing values, XY/curve bindings, layers, axes/ranges/ticks, text/runs and graph geometry.
6. Independently load/cold-reopen in real Origin and inspect rendering. If testing literal minimal patches, avoid a diagnostic Save that would rewrite the candidate and obscure what was tested. Distinguish successful load, approved native Save, cold reopen and emitted preview.
7. Separately synchronize and verify the relevant PPT representations through a supported confirmed path: native payload, external media, internal OlePres cache and PPT host geometry. A good PNG does not prove native editability or refresh safety. Apply the shared final-size aesthetics and application lifecycle checks.

Do not chain frozen candidates or combine separately tested color/font/geometry patches unless that composition itself has a verified implementation and approved plan. Machine-specific font IDs, palette encodings, source offsets, graph-page/layer values and raw dimensions cannot be copied to another source or converted to PPT mm/pt without independent measurement. Do not resume paused reverse engineering just because a current source is unsupported.

## Three route implications

- **Python:** the shipped code route supports bounded external-preview and inspection operations. A separately supplied exact-source patch remains separate, restricted and permission-gated; this reference is not executable support for arbitrary native edits. Warn about format changes or preview restoration when Origin reopens/refreshes.
- **Windows Origin MCP:** discover the real installed tools and capability. The toolkit's historical files do not prove any MCP is connected or safe to operate. Use a bounded copy/operation and native/PowerPoint validation.
- **Mac VM command-line bridge:** require the reviewed current worker and authorized finite session. Bind source/candidate/worker hashes, per-round paths, allowed operations, sequence and structured stage evidence. A completion marker proves process completion only; verify actual stages and source identity. Do not start watchers, listeners, shared-folder permissions or persistent access as an implicit part of reading the toolkit.
